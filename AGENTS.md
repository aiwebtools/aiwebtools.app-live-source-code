# Architecture Rules
- Render tool explanations from catalog descriptions; directory comprehension must not require paid AI.
- Keep the music theater inside its own eager loading/error boundary with explicit retry and a dedicated static shell; failed route imports must not reload into directory content or hide player controls behind readiness messages.
- Resolve studio header subtitles through the complete display-only purpose-description catalog, never archive taglines or name-repeat templates; reject setup text, greetings and file artifacts, and keep headings single-copy so internal identities and prompts cannot leak.
- Send administrator notifications through the linked Gmail account using one shared recipient list and branded HTML frame; never silently reduce owner recipients or claim unsent mail succeeded.
- Submit Enter searches only to an exact normalized name; otherwise retain the typed query and its results instead of opening unrelated suggestions.
- Keep service packages shared between intake and the services page; save requests before Gmail/Calendar delivery and show payment collection as unavailable until a real checkout is configured.
- Read persisted provider circuit state for studio model eligibility; unavailable manual selections must remain disabled without silently changing personal providers.
- Use the anonymous, validated Pollinations picture backup only after image credit exhaustion; retain private image storage and never bypass denials/refusals.
- Handle active-frame music completion once per video after playing; never infer completion from resetting wall clocks or advance paused book clips with duration timers.
- Preserve Vite development URLs returned by ES image imports in the shared image resolver; rewriting them hides valid card and page art.
- Resolve existing active-bot intro recordings through website asset pointers before invoking Supabase; preserves voices in clones without regenerating audio, while private chat pictures stay in access-controlled storage.
- Resolve verified compressed community portraits through `migratedBotMedia` in both live catalogs, retaining byte-identical originals as backups; exact source matching preserves new uploads and reduces picture transfer size.
- Subdirectories may have their own `AGENTS.md`; read it before changing files there.
- Queue deferred mounts cancellably with lazy fallbacks to prevent loading gaps.
- Load homepage content as dependencies of its existing lazy route, never through deferred mount queues; route-ready must represent real sections, while decorative effects stay deferred.
- Share companion links across device menus to keep destinations consistent.
- Keep official social identities and verified audience snapshots in one catalog; share the Socials destination across device menus and leave unavailable counts unknown.
- Use subject metadata, not themes; lazy-load unpublished survival brains only in the existing builder.

- Wrap routes once with the persistent browser unlock gate; retain deep links and explicit legal consent, without chained welcome or music entry dialogs.
- Surfaces outside the router use the shared in-app navigate listener to preserve single-page navigation.

- Schedule automatic promotional dialogs through the shared session-wide scheduler so navigation and competing pop-ups cannot bypass the cooldown.

- Reuse `DownloadLibraryButton` for library entry points and the shared PDF resolver for separate archived/authored community manifests; this prevents divergent downloads.
- Resolve hosted chatbot speech through `getGptVoiceProfile`; this keeps character-inspired voices consistent without cloning real people.
- Serialize hosted and device response speech via one completion-aware queue (Voice Studio voices first; device voice only when out of credits); cancel welcome/waiting voices and stale audio before replies so fallback cannot overlap or lose sentences.
- Keep optional voice playback isolated from text delivery and capability-check both device speech APIs; missing phone voices must never truncate displayed or saved replies.
- Unlock hosted speech on submit and voice enabling, before network waits, so gesture-restricted browsers auto-read replies.
- Prime device speech separately in submit/play gestures, retain utterances until completion, and select natural language-matched voices; Web Audio failures must not suppress free fallback and device failures must be visible and logged.
- Use cancellable one-utterance mic sessions; release capture before voice submission and resume hosted speech to prevent feedback and silent replies.
- Render hosted bot rooms through `BotStudio` in both embedded and full-page placements so voice, streaming, downloads, branding and guest history cannot diverge.
- Scope commercial events to their own iframe, layer them above studio dialogs, and stop playback before dismissal; unrelated players must never hide a sounding commercial or block chat.
- Keep studio drawers above embedded dialogs and close their parent dialog before route changes; phone bot switching must never remain hidden behind the previous room.
- Apply offscreen paint containment only to individual tool cards, never all nested grids; homepage sections and studio controls must stay visible across browsers.
- Expand homepage tools through the existing guarded incremental loader, never by mounting the entire catalog on one click; bounded batches preserve click and scroll responsiveness.
- Store device conversations separately by bot and thread, with dedicated `/app/:slug/chat/:threadId` URLs so reloads restore the exact conversation.
- Carry actual routed model and normalized provider usage in stream metadata and device history; aggregate tool rounds, never infer billable tokens from text or cover chat controls.
- Keep studio image download/revision actions in `StudioImageActions` and route revisions through the existing conversation so generated visuals retain story context.
- Parse documents in the ES worker/PDF.js and send validated resized photos through existing transport; retain bounded context and reject unsupported binaries.
- Visitor community GPTs publish via publish-community-gpt (ethics review); the archived library imports verbatim via secret-gated upsert-only seed-community-library. Variants are `<base>-vN` rooms grouped by `botFamilyKey`; page catalog reads by 1000.
- Device-only custom bots use custom- slugs and send their own instructions to run-gpt-app; they are never stored server-side or in conversation history.
- Share chat/sidebar portrait lookup; lazy-load remote art over a local subject fallback to prevent blanks and image-request floods.
- Read live community GPTs through `communityBots.ts`; use the shared identity map for public names/missing art, preserving slugs, prompts and existing media.
- Resolve exactly one studio starter through `getBotStarters`, with purpose overrides, version-family reuse and name-based fallbacks instead of raw taglines; this keeps imported instructions out of compact starters without changing any brain.
- Keep reply celebrations in a bounded local canvas/audio helper with explicit mute and reduced-motion support so effects never add AI costs or block replies.
- Close the bot drawer before opening the builder; reuse saved drafts on review retries to prevent duplicates. Persist chosen voice and validated uploaded avatar through publication so public and device identities match.

- Unlock generated-audio contexts from the initiating click and reuse decoded clips for replay; homepage audio controls must never regenerate on replay.
- Generate sound effects server-side through the linked ElevenLabs account, preserving provider errors and keeping its key out of the browser.
- Build web workers as ES modules (`worker.format: "es"`); the attachment worker code-splits and IIFE workers fail the build.
- Log every bot failure (gateway, search, image, attachment, analysis, dropped stream) to gpt_chat_logs with a distinct status, including browser-side reports, so chat-watchdog alerts on all of them; show search failure once per reply and keep notices out of speech.
- Record visits, clicks and bot opens only through `siteTracker` (batched rows with identical keys into `site_events`); one tracker keeps data consistent and off the click path.
- Pre-mount large header menus during idle (forceMount + hidden when closed) so the first tap only reveals them.
- Community apps are listed from `community_apps` and only inserted by the AI-reviewing `submit-community-app` function; keeps unverified links out of the menu.
- Keep personal keys in owner-bound page memory and authenticated chat requests, never storage/tracking/logs; explicit activation cannot silently fall back to paid default AI.
- Select builder-paid chat transport server-side behind the existing tool loop with Lovable first and pre-stream Bionic backup, retaining personal-provider precedence and separate image/search/speech services; persistent circuit states prevent denial/refusal bypass.
- Run background helper text jobs (Care Bot, weekly digest, community-app review) through `_shared/glm-helper.ts` first, keeping their existing Lovable AI call as fallback; search tool matching and ethics review stay on gateway models for speed/strictness.
- Request 1080p once on video startup, with sound-on autoplay outside cards; honor provider availability and user controls without background quality/pause/play loops.
- Share one lossless MTVAI catalog union across pinned, vertical, book and theater players; counts and first-track identities must not diverge between surfaces.
- Add verified channel batches to the shared recent-upload source; music queues exclude audiobook IDs and removed uploads so all player entry points retain the same separation.
- Render the preserved full-book PDF through the existing PDF.js library; third-party document embeds must not be the only readable preview.
- Use generated directory totals for first-paint counts and actual catalog length for exports; distinct metrics must be explicitly labeled.
- Count studio category rooms including every family version, matching the shared catalog total; filtered counts describe matching rooms, tool-category totals exclude appended recommendations, and public fallback snapshots mirror active directory rows. Tool-page static and rendered metadata use the shared displayed-category resolver to prevent first-paint drift.
- Reserve a separate floating lane for Clone while Care Bot is open and contain phone conversation scrolling; controls must not cover one another.
- Lead every MTVAI music queue with the shared channel upload order rather than randomizing new additions; preserve legacy identities and keep chronological metadata unknown when unverifiable.
- Render the music-channel signature through MtvaiBrand across header, footer and players; shared attribution prevents branding drift while preserving the main directory identity.
- Reuse the lazy MTVAI audiobook collection across theater, pinned and book entry points; verified channel IDs and catalog union preserve recordings, and opening it suspends competing playback.
- Scope exact intake-paragraph deduplication to screenplay-writer streams, preserving other prose and bot output; repeated model questions must not duplicate displayed or saved intake.
- Keep Muse offer code, join link and copy fallback in `components/muse/museOffer.ts`; banner, popup and tool page share it so the code cannot drift, and the offer voice plays from one cached recording.
- Use getUserMedia for first mic permission, then start recognition synchronously in the tap once granted (Safari); keep voice-input callbacks in refs, and allow `microphone=(self)` in Permissions-Policy; blocked policy or unstable callbacks silently kill dictation.
- Prioritize exact discovery names after merging community suggestions; test the public search worker against its shipped catalog so source-only ranking tests cannot hide live regressions.
- Derive directory counts, category membership and paginated filters from the same name-unique catalog; use purpose metadata rather than incidental prose, sort alphabetically before pagination, and preserve source records and bot versions when hiding duplicate listings.
